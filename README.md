# الجوهرة نت 2 — Jawhrah2

بوابة HotSpot عربية محلية لراوتر MikroTik RouterOS v6. تحتوي صفحة تسجيل الدخول الكاملة والتصاميم والخدمات وحالة الرصيد ونقاط البيع وآخر كرتين والثيمات المختلفة، دون الحاجة إلى شبكات CDN.

## التركيب الآمن

1. خذ نسخة احتياطية من مجلد HotSpot النشط، وتأكد أن سيرفر التجربة يستخدم نفس إعدادات `login-by` وRADIUS/User Manager. **لا تستبدل صفحة الإنتاج دون الاختبار أولاً.**
2. ارفع ملفات جذر المشروع ومجلدات `css` و`js` و`font` كاملة إلى مجلد HTML الخاص بهوتسبوت الراوتر. ملف `js/chap-md5.js` **ضروري**، ولا تحتاج إلى مكتبة MD5 من الإنترنت.
3. افتح مسار الراوتر **`/login`** (وليس `login.html` كملف ثابت). `index.html` يحول إليه آلياً حتى يفسر الراوتر متغيرات `$(chap-id)` و`$(chap-challenge)` و`$(link-login-only)`.
4. يدعم النموذج `HTTP-CHAP` عندما يتيح الراوتر تحديه في صفحة الدخول، ويستخدم إرسال كلمة مرور عادية فقط عندما لا تتوفر بيانات CHAP. **إذا كنت تستخدم HTTP-PAP فوق HTTP فلن تكون كلمة المرور مشفرة أثناء النقل؛ استخدم HTTPS بشهادة صحيحة أو إعداد CHAP ملائماً.** لا تغيّر `login-by` مباشرة على أجهزة العملاء لأجل هذا المشروع.
5. جرّب سيناريوهات الحساب الصحيح، والخاطئ، والمنتهي، والمشغول على جهاز آخر، وانقطاع الشبكة، ثم تأكد من تسجيل الخروج وتوافق الروابط مع إعدادات الراوتر.

## تحسينات النسخة r7

- ظهور واجهة الجوهرة نفسها على `/login` بدلاً من النموذج المختلف الذي كان معروضا هناك.
- استجابة `HTTP-CHAP` باستخدام MD5 محلي لا يرسل كلمة المرور بصيغتها الصريحة عندما يتوفر تحدي CHAP. عند الرفض، تعاد زيارة `/login` لتوليد تحدٍ جديد **من دون حفظ كلمة المرور لمحاولة تلقائية**.
- الحفاظ على نموذج HTML احتياطي عند إيقاف JavaScript؛ هذا النموذج لا يستطيع تنفيذ CHAP، ويمكنه العمل فقط إذا قبل إعداد الراوتر نوع دخول مناسباً.
- اختيار صريح لحفظ آخر كرتين وكلمات المرور على الجهاز (غير محدد في الجهاز الجديد). لكل كرت مدة صلاحية مستقلة 30 يوما؛ تبقى البيانات المخزنة سابقاً ضمن مدتها، ويظل زر مسح السجل متاحاً. تتوقف الاستعادة الآلية للكوكي القديم مجهول العمر حماية للخصوصية.
- تحديث الحالة كل 30 ثانية في الصفحة الظاهرة، و60 ثانية في الخلفية، مع إبطاء المحاولات عند الإخفاق. توجد طلبات تحقق أسرع عقب الدخول عندما لم تؤكد الجلسة بعد.
- تخفيف بعض الظلال والحركة على Android/WebView القديم مع الاحتفاظ بحركة شعار واحدة، وتغيير بصمة الكاش إلى `jawhara-priority-r7`، والاستفادة من روابط الراوتر الديناميكية.
- تصحيح رسالة `no valid profile` إلى «لا توجد باقة فعالة لهذا الحساب»، وتسميـة الباقي «البيانات المتبقية».

## الفحوصات

```sh
node --check js/portal.core.js
node --check js/chap-md5.js
node tests/test_chap.js
node tests/test_diagnostics.js
python -m unittest discover -s tests -v
```

لتشغيل اختبارات المتصفح، ثبت `playwright` وChromium وشغّل `RUN_BROWSER_TESTS=1 python -m unittest discover -s tests -v`. في GitHub Actions هناك مساران متوازيان: اختبارات المصدر واختبارات المتصفح مع محاكاة RouterOS. نجاحها لا يثبت نتيجة على راوتر فعلي أو على كل هواتف العملاء.

## الخصوصية والحدود

حفظ كلمات المرور في `localStorage` بعد تفعيل الخيار لا يشفرها. لا تستخدمه على هاتف مشترك، وامسح آخر الكروت إذا انتقل الجهاز لمستخدم آخر. ملفات هذا المشروع لا تغير إعدادات الراوتر، ولا يمكن التحقق من `login-by` الحقيقي من المستودع فقط. يجب التحقق منه قبل تعميم النسخة.

## تحديث r8 — ملفات النشر المعتمدة

- تعديل خصوصية سجل الكروت: إلغاء خيار الحفظ يمسح اسم المستخدم وكلمات المرور القديمة من المخزن المحلي، ولا تستورد النسخة الحالية كلمات مرور قديمة دون موافقة صريحة. **ملاحظة:** عند اختيار الحفظ، تظل كلمات المرور المخزنة محليا قابلة للقراءة على الهاتف.
- لا يتم تغيير أرقام كلمة المرور العربية تلقائيا؛ يتم تحويل الأرقام العربية في **اسم المستخدم فقط**.
- دعم صيغ مدة الاتصال المختلطة مثل `1d02:30:45` مع الاحتفاظ بدقة الساعات والدقائق والثواني.
- جدولة تحديث حالة الاتصال بحسب ظهور الصفحة لتقليل الطلبات غير الضرورية.
- تشغيل اختبارات Chromium بجانب الفحص الثابت، ثم تغليف الملفات التشغيلية فقط إن نجح كلا المسارين.
- إنشاء حزمة تشغيل موحدة بمحتويات محددة وبصمة SHA-256:
  `python scripts/build_hotspot.py --output dist`
- عند التركيب ارفع **محتويات ZIP مباشرة إلى مجلد HTML النشط** على الراوتر (لا ترفع ZIP نفسه)، مع نسخة احتياطية واختبار `login-by` على راوتر تجريبي أولاً.
- لا يتضمن المشروع ملفات Windows Portable/Installer؛ هذا مشروع بوابة HTML/CSS/JS للمايكروتيك.
